# Architecture & System Boundaries

Non-obvious integration constraints for the local Live pitch demo.

- Revision 5 fixes tab selection visually: a temporary native child host inside AModeSwitchControl renders both stock tabs inactive only while Pitch is open. Remove it before forwarding mouse-down within its actual screen bounds; Sample and Envelopes transitions were verified. This does not change Live's content-mode enum. Typography loads the installed Ableton Sans Small font; colors currently target Default Dark Neutral Medium.

- Current native implementation supersedes the earlier "no host attachment" findings below: `pitchnative4` creates `APlatformViewHost` children inside both the resource tab button and `LWarpedAudioTimelineEditor`, with actual `TPlatformViewContainer` NSViews. Tab opening, source analysis, keyboard editing, local undo/redo and tab-toggle retention were verified; audio rendering and viewport mapping are still missing. See `docs/native-tab-working.md`.
- `TAxButtonElement` inherits the same weak proxy storage but uses `AButtonControl::CreateAxProxy()::TButtonControlAxProxy`; checking only a `TAxProxy` name substring rejects it. The proxy's +0x28 owner is the native `AButtonControlSimple`. Native factory TPtr returns require x8; the tested add-child path takes `(parent, child, insertionSibling)` and retains the child.
- Live consumes ⌘Z before a hosted AppKit canvas's `keyDown:`; without app-local interception scoped to the active canvas, undo removes the Max loader. `pitchnative4` scopes key handling to `window.firstResponder == canvas`, and undo/redo was verified against the note accessibility value.

- The installed Live 12.4.5 Trial arm64 binary exports named Clip View callback wrappers, including content-mode and editor-tab handlers. Use filtered `nm -arch arm64 -gU ... | c++filt` searches; the complete symbol listing is enormous. Names alone do not establish a safe ABI or object layout.
- Desktop Clip View uses XML inside `Contents/App-Resources/GUI.alp`, not the Qt/Push QML. `ClipContentHeader.xml` contains `ModeSwitchControl` / `EditorViewModeSelector`; a sibling `ButtonControlSimple` was rendered and observed in Live as `ClipDetailView.ClipContentHeader.PitchEditorButton`. See `docs/native-tab-resource.md`.
- Native bottom-panel integration is an explicit requirement. Do not substitute an overlay, Max device panel or separate plugin window and claim the requested demo is complete.
- Code signing inspection reports hardened runtime. Entitlement extraction emitted an invalid-blob warning, so effective entitlements remain unverified; do not infer an injection path from that warning.
- The normal demo UI allows loading a stock audio clip and opening Clip View. Its Sample/Envelopes selectors correspond to candidate `AClipContentHeaderViewModel` mode callbacks; the AX editor ID is `ClipDetailView.WarpedAudioTimelineEditor`. An AX container is not proof of an independently attachable AppKit view.
- Verified loading path: a custom arm64 Max external in a local `.amxd` executes inside `com.ableton.live`, including main-thread dispatch. This required neither Live re-signing nor executable patches. It does not demonstrate permission or an ABI for registering internal Live editors.
- Runtime inspection establishes `TAxPlatformNode : NSAccessibilityElement`; Clip View and the waveform editor are virtual accessibility nodes, not native AppKit subviews. `TCocoaMainView : NSView` hosts the main drawing surface. Do not call `addSubview:` on AX nodes or label an AppKit cover view as native mode integration.
- Live's virtual nodes use modern accessibility selectors. Calling only deprecated `accessibilityAttributeValue:` can return nil or omit Live's tree, falsely suggesting no accessible Clip View. Inspect on the main thread and use `accessibilityChildren`, `accessibilityIdentifier`, and `accessibilityFrame`.
- Offline tracing confirms tab setters select 0/1/2, the effective-mode controller sends 0 for other values, and keyboard cycling uses modulo 3. A fourth tab requires coordinated changes; enabling an extra enum/filter alone is insufficient. See `docs/native-tab-trace.md` and reproduce with the fingerprint-guarded `scripts/trace_tabs.py`.
- Ordinary debugger attachment to Live was denied by macOS even after shell escalation. Do not describe static disassembly as live tracing or assume another sandbox approval will fix attachment. No debugger permissions, Live signatures or system security settings have been altered.
- Native placement is now proven by a resource-only change in the experimental app copy. The new button is disabled because it has no action binding; do not describe it as a working mode or pitch editor. The existing selector gets labels from a native enum, so XML children alone cannot extend its modes.
- `Pitch Editor Lab.app` is a standalone regression harness, not the native Live integration. Its `pitch::Document` undo is local, pitch offsets do not yet resynthesize audio, and source-time seconds are not warped Live beat coordinates; do not claim host undo, audible editing, or clip synchronization.
- `Pitch Editor.amxd` / `pitchclip2.mxo` now demonstrates the same detector/model in Live's Device View. `live.path` resolves `live_set view detail_clip`, `t b l` sets the `live.object` ID before requesting `file_path`, and the adapter reads the full source; selection does not imply crop/warp mapping. This does not activate the experimental native Clip View button.
- Max allocates external structs as raw storage: keep C++ owning members in a separately constructed `Model`. Background analysis captures only shared pending state, never a Max object pointer; result installation/redraw is marshalled through a qelem, and teardown frees the clock/qelem before deleting the model.
- `APlatformViewHost` is a newly traced internal mounting candidate; factory/callback addresses and ownership observations are in `docs/native-tab-trace.md`. Its `TPtr<ACompound>` factory uses arm64 indirect return and its native-handle callbacks move `StrongRef` values: neither is safely callable through a guessed `void*` ABI. `pitch_canvas.mm` is now independent of the lab window, but no host registration or native tab activation has been established.
- `inspect_clip_layout.py` identifies empty runtime-populated `_ClipContentContainer` between native header/footer; footer binds three cards to `EffectiveContentViewMode`. Sample/Envelopes UI comparison preserves audio timeline/loop AX IDs while removing envelope footer controls, so investigate a native pitch layer sharing the audio timeline before replacing the entire editor. AX IDs alone do not prove C++ object identity; see `docs/native-pitch-integration-path.md`.
- Probe revisions 4/5 now prove identical native owner pointers across both Sample/Envelopes transitions for the tested audio clip: `LClipDetailView`, `LWarpedAudioTimelineEditor`, and `ALoopMarkerParentClipDetail`. AX nodes expose a weak `TAxProxy`; its +0x28 owner is validated by RTTI using read-only Mach reads. Do not generalize one clip's lifetime to other clips or invoke private methods through these pointers.
- Runtime fields establish Clip Detail +0x310 → `AClipContentEditor`, then +0x2d8 → `LDetailTimelineArea`; Clip Detail +0x438 matches its +0x3e0 warped editor. Editor +0x390/+0x3a0/+0x308 match Clip Detail's audio clip/view model/zoom bounds. The area's vtable +0x590 resolves to 0x103cc72cc and forwards child attachment to a nested view, so it is not a simple AppKit mount point; see the integration report for remaining ABI work.

- Typography correction (revision 7): use 10-point Ableton Sans Small for the hosted tabs. Both 12 and 11 points were too large. Compare exported native and hosted screenshots, not just the selected view: at the tested UI scale, Sample bright-text bounds measured 26 × 6 pixels in both native and revision 7 captures (threshold 100); the hosted baseline is still one screenshot pixel higher. Evidence is in build/research/font-original.jpg and font-corrected.jpg.

- Revision 10 supersedes all earlier tab appearance guidance: never redraw Sample/Envelopes. Verified AModeSwitchControl setters 0x10358ca48 and 0x10358ca78 change selected background/text IDs (+0x32c/+0x334); copy unselected IDs (+0x330/+0x338) while Pitch is active and restore on exit. Keep a native TPtr reference (+8 retain; release 0x10358bc80) for lifecycle safety. See docs/native-tab-working.md.
- Even an empty or hidden APlatformViewHost inside AModeSwitchControl suppresses its original native drawing. Removing the host entirely restores the labels; derive pointer hit bounds from native rectangles instead. Pitch's own label must keep the same font AND text color across states; change only its background.

- Navigation revision 14: the canvas has its own bounded source-seconds/pitch viewport and inner ruler; never claim synchronization to Live's outer beat ruler. App-local scroll/magnify interception must be restricted to pointer-inside-canvas; Live otherwise consumes scrolling before the hosted NSView. Restore canvas first responder asynchronously on mouse-up, since Live steals focus after a ruler drag; Fit was verified after this fix.

- Playhead revision 17: do not assume Clip.playing_position/is_playing work for Arrangement clips. Both stayed zero during verified playback here; use Song current_song_time/is_playing plus Arrangement start/end/start_marker and loop mapping, then interpolate Clip warp_markers to source seconds. The warp dict has a warp_markers array of dictionary atoms with beat_time/sample_time, including a hidden final marker. Native polling is qelem-driven from a 30 Hz timer only while the canvas is open; all painting stays on the main thread. See docs/native-tab-working.md for unverified cases.

- Cursor revision 18 supersedes the Logic-style embellishments: use a plain neutral gray line with no cap or per-note playback highlight, matching the observed Envelopes view. Read Song.View.follow_song for local paging; manual pan/zoom suspends local following until transport restarts or the switch changes. The seconds viewport is still independent of native beat zoom; do not call this native cursor reuse or exact continuous-scroll parity.

- Palette revision 19 uses Default Dark Neutral Medium roles: DetailViewBackground #3e3e3e, SurfaceBackground #363636 and DetailViewRulerMarkings #919191. Pitch-row and grid shades are opaque composites of the theme’s MIDI/grid alpha colors over the detail background, avoiding translucent fill differences in hosted views. These are fixed palette values, not live theme synchronization.

- Waveform revision 20 displays the original analysis channel, not processed audio or a native Live waveform view. Keep it in source seconds alongside notes/cursor, independent of vertical pitch pan; stereo analysis selects the strongest AC-energy channel. Changes to Analysis layout require rebuilding every consumer used in the session, in addition to renaming the cached native/Objective-C classes.
