# Architecture & System Boundaries

Non-obvious integration constraints for the local Live pitch demo.

- The installed Live 12.4.5 Trial arm64 binary exports named Clip View callback wrappers, including content-mode and editor-tab handlers. Use filtered `nm -arch arm64 -gU ... | c++filt` searches; the complete symbol listing is enormous. Names alone do not establish a safe ABI or object layout.
- Desktop Clip View uses XML inside `Contents/App-Resources/GUI.alp`, not the Qt/Push QML. `ClipContentHeader.xml` contains `ModeSwitchControl` / `EditorViewModeSelector`; a sibling `ButtonControlSimple` was rendered and observed in Live as `ClipDetailView.ClipContentHeader.PitchEditorButton`. See `docs/native-tab-resource.md`.
- Native bottom-panel integration is an explicit requirement. Do not substitute an overlay, Max device panel or separate plugin window and claim the requested demo is complete.
- Code signing inspection reports hardened runtime. Entitlement extraction emitted an invalid-blob warning, so effective entitlements remain unverified; do not infer an injection path from that warning.
- The normal demo UI allows loading a stock audio clip and opening Clip View. Its Sample/Envelopes selectors correspond to candidate `AClipContentHeaderViewModel` mode callbacks; the AX editor ID is `ClipDetailView.WarpedAudioTimelineEditor`. An AX container is not proof of an independently attachable AppKit view.
- Verified loading path: a custom arm64 Max external in a local `.amxd` executes inside `com.ableton.live`, including main-thread dispatch. This required neither Live re-signing nor executable patches. It does not demonstrate permission or an ABI for registering internal Live editors.
- Runtime inspection establishes `TAxPlatformNode : NSAccessibilityElement`; Clip View and the waveform editor are virtual accessibility nodes, not native AppKit subviews. `TCocoaMainView : NSView` hosts the main drawing surface. Do not call `addSubview:` on AX nodes or label an AppKit cover view as native mode integration.
- Live's virtual nodes use modern accessibility selectors. Calling only deprecated `accessibilityAttributeValue:` can return nil or omit Live's tree, falsely suggesting no accessible Clip View. Inspect on the main thread and use `accessibilityChildren`, `accessibilityIdentifier`, and `accessibilityFrame`.
- Offline tracing confirms tab setters select 0/1/2, the effective-mode controller sends 0 for other values, and keyboard cycling uses modulo 3. A fourth tab requires coordinated changes; enabling an extra enum/filter alone is insufficient. See `docs/native-tab-trace.md` and reproduce with the fingerprint-guarded `scripts/trace_tabs.py`.
- Ordinary debugger attachment to Live was denied by macOS even after shell escalation. Do not describe static disassembly as live tracing or assume another sandbox approval will fix attachment. No debugger permissions, Live signatures or system security settings have been altered.
- Native placement is now proven by a resource-only change in the experimental app copy. The new button is disabled because it has no action binding; do not describe it as a working mode or pitch editor. The existing selector gets labels from a native enum, so XML children alone cannot extend its modes.
