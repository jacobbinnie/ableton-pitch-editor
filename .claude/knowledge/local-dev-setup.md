# Local Development Setup

- Build the working native adapter with `python3 scripts/build_native.py`; load `Native Pitch Editor.amxd` with the versioned `.mxo` named by `scripts/build_native.py` beside it in the experimental app. The native copy must already have the resource tab. The build checks its executable hash. The read-only probe and 20-second mount test are optional research tools, not additional required devices.

- This project must have its own `.git` directory. Before initialization, Git walked upward into `~/.git`, exposing unrelated home-directory changes. Always verify `git rev-parse --show-toplevel` equals this project before staging or committing; never stage the parent repository. App copies and extracted resources stay under ignored `build/`.

- Use bounded LLDB offline `disassemble --start-address ... --end-address ...` for Live code inspection. Xcode's `llvm-objdump --macho --disassemble` ignored the supplied start/stop bounds in this environment and emitted the full text section; do not use it for targeted output. `scripts/trace_tabs.py` captures a bounded, fingerprint-verified set of ranges without launching or attaching to Live.
- All recorded code addresses are arm64 file virtual addresses for the exact hashed build, not live ASLR addresses. An updated application requires re-identifying the symbols and code, not replacing the hash and reusing the old map.
- `scripts/prepare_tab.py` patches only `build/Ableton Pitch Lab.app/Contents/App-Resources/GUI.alp`. Create the copy once using macOS `cp -cR`; close that copy before regenerating resources, which Live caches. Keep extracted proprietary XML, archives, and application copies under ignored `build/`.
- Original and experimental apps have the same bundle ID. CUA must use the full app path or resolution is ambiguous. Concurrent Live instances warn that crash recovery is unavailable and share preferences; use scratch Sets. The resource-only copy launched on this Mac without re-signing, but its changed resource seal is not valid for distribution.
- CUA may transparently relaunch an app when querying its state after quitting. For resource rebuilds, quit the disposable copy, rebuild without another app-state query, then reopen and inspect. Do not mistake the automatically relaunched instance for a failed quit.
- `BorderProperty` requires numeric `ColorName` and `CornerColorName` attributes (e.g. 56 and 1 from the existing header), unlike `ColorNameProperty`, which accepts symbolic names. Symbolic border values cause a startup XML exception; inspect Live's preferences `Log.txt` for the exact field before retrying.
- New BorderedCellView wrappers need explicit fixed horizontal/vertical sizing and zero layout weight. `PointProperty Size` must also be set on the wrapper: fixing its initial zero size makes it disappear. Default expansion stretched the Pitch button wrapper and pushed the stock selector left. Use the original header row with gap zero rather than adding an expanding nested row.
- Build the independent detector and UI harness with `python3 scripts/build_editor.py`; it needs only the macOS compiler/frameworks, not the Max SDK. Close the running harness before rebuilding and relaunch it to exercise updated code; replacing its executable does not update the already-running process.
- `scripts/build_live_editor.py` builds the Max UI external and companion device using the pinned SDK. `pitchclip2` supersedes the first in-session cached class; keep the matching `.mxo` beside `.amxd`, and restart Live before expecting a rebuild of the same class name to take effect. The specific method-pointer cast warning is suppressed because Max's registration API uses its generic `method` typedef for differently typed callbacks.
- `scripts/build.py` currently emits `pitchprobe6.mxo` and `Pitch Probe.amxd`; the probe schedules 24 read-only snapshots every five seconds after loading. Switch Sample/Envelopes while Clip View is visible, then run `scripts/analyze_probe.py`; it correlates owners within the latest observed process and uses envelope-footer visibility only as a controlled-test mode indicator. Revision 6's additional timeline-area field survey is built but not runtime-verified; the verified owner evidence came from revisions 4/5.

- Revision 5 uses new Max and Objective-C tab/action class names to avoid in-process caching. Remove the previous loader before opening the rebuilt device; rebuilding a loaded class does not update its code.

- Preferred varied-note audio fixture: `fixtures/local/track-3-vocal-pitch-demo.wav` (track 3 recording, copied with its .asd outside build/). Use it for editor demos; the current detector produced 10 segments. Audio is Git-ignored and must be supplied separately on another machine.

- When changing PitchCanvas while Live remains running, rename the Objective-C class too (the native build uses -DPitchCanvas=PitchCanvas14). Renaming only the Max external leaves the old Objective-C implementation registered. Viewport tests run via scripts/build_editor.py alongside the existing core tests.

Dependency source and linked binaries are ignored; this local experiment does not establish distribution licensing. CLI refuses existing output paths; use fresh names when rerunning examples.
